# 本机测试群排障助手

这是运行在公司电脑上的 DeepSeek Harness 扩展：轮询测试群中的 **@开发** 消息，在独立 Agent 会话内追问、查服务目录、读代码、查 Docker 日志，再回复有证据的诊断。

Agent 循环、模型调用、会话历史和图片处理复用 Harness。本项目不维护另一套模型 API Key，也不自建 Agent 循环。

## 现在可以直接体验

已在本机 **DeepSeek Harness 桌面版 0.2.2-rc.1** 实际验证。全局 `dsh` 是旧版本时，启动脚本会优先使用桌面应用自带的 CLI。需要 Node.js 22 或以上，无需 npm install。

在项目根目录打开两个终端：

```sh
npm run mock
```

```sh
npm start
```

打开 [模拟测试群](http://127.0.0.1:4317)。等待右上角显示 Harness 已连接，然后：

1. 点击“模拟：截图报错”。这会发送一条 @开发 的问题，附带真实 PNG 样例截图。
2. Agent 缺少接口和故障时间时会在群里追问。
3. 点击“填入接口与时间”，再点击“发送消息”。补充信息会引用助手消息，继续原来的会话。
4. 等待诊断：订单服务 → 库存服务 → 日志中的 CACHE_NAMESPACE 为空。右侧可展开证据及调用轨迹。

也可以运行真实模型集成检查（需要前面两个进程已启动，会产生模型调用）：

```sh
npm run demo
```

停止并重启 `npm start` 后，还可验证继续原来的 Harness 会话：

```sh
npm run demo -- --resume
```

自动化检查（不会调用模型）：

```sh
npm test
```

模拟聊天、代码、部署目录和日志都是本地样例。诊断由已配置模型实际调用工具完成；`demo` 检查脚本不生成诊断结论。样例故障时间固定为 **2026-11-09 02:00:00 +08:00**，用于历史事件回放，与当前消息发送时间无关。

## 本机运行和模型配置

`npm start` 创建独立的 `troubleshooting` profile，启动配套 Harness Web 运行时（127.0.0.1:4318）。保留桌面版日常配置；只读取源 profile 的默认模型选择，并通过 Harness 原有凭证存储使用连接。该 Web 运行时是 Harness 本身，不是额外的自研 AI 后端。

可配置启动环境变量：

| 变量 | 用途 |
|---|---|
| `DSH_CLI` | 指定公司电脑上的配套 Harness CLI 路径 |
| `DSH_SOURCE_PROFILE` | 默认 `desktop`，读取其中默认模型选择 |
| `DSH_TROUBLESHOOT_PROFILE` | 默认 `troubleshooting`，独立调试 profile |
| `TROUBLESHOOT_CONFIG` | 默认 `config/demo.json`，可换公司配置文件 |
| `HARNESS_PORT` | 默认 4318 |

目前已验证内置 `deepseek-official` 连接。若公司的模型依赖额外的 provider 插件或专属 profile 配置，需要在独立 profile 中安装/配置相同 provider，或把本插件加入已有 Harness 配置；**只复制模型名称无法自动复制自定义 provider**。本机模拟已验证复用原有连接，但尚未验证公司的实际模型适配器。

## 回公司后替换哪些部分

提供一份常见问题列表即可启用知识检索；支持本地 Markdown/JSON，也提供公司知识库适配接口。Agent 阅读资料后判断适用条件，能直接答复的无需查运行日志，仍需验证的问题继续排查。见 [常见问题与知识源扩展](docs/knowledge.md)。

需要登录部署后台查看 YAML 时，见 [BrowserSkill 接入与模拟步骤](docs/deployment-browser.md)。后台入口可配置，页面登录和导航由 Agent 使用原生浏览器工具决定。

公司电脑是 Windows 时，按 [Windows 公司使用步骤](docs/company-windows.md) 操作；环境和 SSH 模板位于 `config/`。

详见 [接入协议](docs/integration.md)。可以先保持 Skill 和 Agent 接入不变，只替换群接口，提供服务器清单和代码根目录，并把日志查询模式从 `mock` 改成 `ssh`。

核心位置：

- `src/plugin.mjs`：Harness 插件入口。
- `src/chat.mjs`：HTTP 轮询适配器；可用自己的适配器模块替换。
- `src/harness-runner.mjs`：通过 Harness 的 agents API 创建和恢复会话，注册该会话的查询工具。
- `.agents/skills/test-environment-troubleshooting/SKILL.md`：排障规则，插件只向其拥有的排障会话加载。
- `fixtures/catalog.json`：模拟环境、服务器入口与代码根目录，不含接口表。

任务、游标、待发送回复、证据保存在 `.local/tasks.json`；模拟群保存在 `.local/mock-chat.json`。独立状态锁防止两个实例重复消费同一群消息。**不要在进程运行中编辑状态文件**。停止前台终端可按 Ctrl+C。

排障会话显式命名为“排障 + 任务编号 + 问题摘要”，命名不调用模型。启动时补齐本插件已有未命名任务；用户已设置的标题保留。桌面端占用的会话暂缓处理，插件每分钟重试未完成的标题补齐，释放占用后再写入；补齐不恢复 Agent，不重新排障或发送群消息。

首次启动从群当前游标开始，避免处理整个历史群聊；后续重启从已保存游标继续。没有新任务时不会调用模型。默认每10秒轮询，失败退避到最多60秒；每轮模型查询有预算和超时。

开发身份引用任务消息可发送 `/暂停`、`/继续`、`/结束`。测试补充需引用该任务的原消息/助手回复，或携带 `#T-xxxxxxxx`。没有明确关联的普通消息不会猜测分配给某个任务。

## 当前边界

- 对业务环境只执行查询，不修改业务数据、配置或部署。允许在排障前快进同步远端代码，不自动修复、提交或覆盖本地修改。
- 运行代码版本关联为可选能力，`versionVerified=false` 时必须标注代码只供参考。
- 已实现固定 SSH 容器发现、日志和状态查询，但本次只验证了模拟日志及 SSH 参数约束，没有连接真实公司服务器。
- 日志解析覆盖带 ISO 时间戳的应用日志、常见 Docker 时间戳包装及多行异常；公司日志格式可能需要适配。
- 截图交给 Harness 附件与模型处理。模型不支持图片时，应向测试索取接口和报错文本；附件读取失败会作为缺失证据呈现。
- 工具结果做常见凭证字段脱敏，不代表能识别所有业务敏感字段。公司接入时按实际字段补充规则。
- 发送幂等性依赖真实聊天适配器支持幂等键或发送结果核对；本地模拟接口已经支持。
- 电脑休眠、退出 Harness 或断网时不会实时处理；恢复后继续轮询。

## 自动发现：不维护接口表

公司配置只需 `environments`、`hosts`（环境与 SSH 别名）、`repositoryRoots`（例如 C:/work/repos）。工具发现 Docker 容器及本地仓库，按请求路径跨仓提取 Spring/Python 字面量路由，再产生服务关联候选。多实例用 instanceId 区分；网关、动态前缀、名称不一致等保留线索和歧义。部署平台自动导入尚未实现。

模拟样例也已移除全部 services/routes 清单，集成测试要求真实 Agent 使用接口检索工具后继续跨服务查询。详见接入协议中的扫描范围、缓存及不完整结果说明。

## 排障前更新代码

公司模式每轮开始前自动发现 Git 仓库，按当前分支的远端跟踪分支 fetch，再执行快进更新。重复目录、多模块和 worktree 路径按 Git 根目录去重；每批最多并发4仓，单条命令30秒、整轮同步120秒超时。同步后清除接口索引缓存，再让 Harness Agent 开始定位。

工作区有修改/未跟踪文件、本地未推送提交、分支分叉、detached HEAD、缺少跟踪分支、认证/网络失败时停止定位并保存同步结果。不会 stash、reset、rebase 或自动切分支；部分仓库失败、未发现仓库或扫描不完整也不会静默使用旧代码。

公司电脑需要 Git 和可用的非交互 Git 登录。建议使用专门的排障 clone，避免与日常未提交工作冲突。同步目标取每个 clone 已配置的跟踪分支，不猜测环境对应的发布分支。暂不自动更新子模块或 Git LFS 内容，相关项目仍需适配。

完整分支、前后 commit 和状态保存在任务 repositorySync 及证据中，并提交给模型；最新 commit 不证明服务器已部署该版本。模拟模式保留固定样例，不执行真实 Git 更新并显式注明。行为参考 [Git fetch](https://git-scm.com/docs/git-fetch) 与 [仅快进更新](https://git-scm.com/docs/git-pull)。
